## Pattern-Erkenntnisse

1. **Frozen-Code-Problem**: ~40% der niedrigen Scores kommen aus eingefrorenen Phase-4-Dateien. Ohne Exclusion wird der eigene Score dauerhaft durch Code belastet, der bewusst nicht angefasst wird. Empfehlung: `docs/checker-feedback.md` Eintrag anlegen.

2. **String-Content-FP**: Checker findet `console.*` in String-Literalen. Das ist P4-Pattern aus `docs/checker-design-patterns.md`. Fix: In den betroffenen Checkern String-Content vor Regex-Match ausschließen.

3. **410-Routes-FP**: Routes die ausschließlich 410 zurückgeben werden als "fehlende Auth" gemeldet. Sonderfall der Stub-Route, der gezielt excluded werden sollte.

4. **Score-Gain gut, Delta +2.0%**: Der Sprung von 93.6% auf 95.6% kam hauptsächlich durch:
   - Design-Polish-Sprint (Farb-System, Buttons, Rounded Corners)
   - Keine tatsächlichen Checker-Korrekturen in diesem Zeitraum
   → Validierung zeigt: Score-Verbesserung war Design-getrieben, nicht Checker-getrieben. Gut für Phase 2.5 Baseline.
